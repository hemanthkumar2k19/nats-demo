# Consumer Testing

## 1. Single Worker Testing

| Failure | Description | How NATS works in this | How to do demo |
| :--- | :--- | :--- | :--- |
| Worker Crash Before ACK | Worker goroutine panics or crashes abruptly after pulling a job from JetStream, before sending an explicit ACK or NAK. | JetStream holds the unacknowledged message in the stream. The server-side AckWait (5s) countdown starts. Server tracks `num_ack_pending: 1` (`Outstanding ACKs: 1`). Because no ACK or NAK arrives, the server marks the message as unacknowledged upon AckWait expiry, increments `num_delivered` from 1 to 2, and redelivers it to the newly respawned worker goroutine. | 1. In Stage 3, expand Failure Lab and click `Arm Crash Before ACK` (or pass `simulate_crash: true` in payload).<br>2. Submit a job in Stage 1.<br>3. Observe worker panic and goroutine termination in terminal (`Active Goroutines: 0`, `Status: CRASHED`).<br>4. Run `nats consumer info JOBS job-processor` to observe `Outstanding ACKs: 1`.<br>5. At t=5.5s, supervisor respawns worker. Watch worker pull redelivery (`Delivery attempt #2`), complete execution, and send explicit `msg.Ack()`. |
| Processing Exceeds AckWait (Late ACK) | Worker pulls a job but business execution takes 7 seconds, exceeding the consumer's configured AckWait (5s) threshold. | During the first 5 seconds, NATS server holds the message as pending ACK (`num_ack_pending: 1`). At t=5.01s, server AckWait timer expires and marks the message for redelivery. When the worker finishes execution at t=7s and transmits a late `msg.Ack()`, JetStream handles the late acknowledgement. | 1. In Stage 3 Failure Lab, click `Arm Exceed AckWait (7s)`.<br>2. Submit a job in Stage 1.<br>3. Observe terminal logging slow processing taking 7s with notice that AckWait will expire.<br>4. Inspect `nats consumer info JOBS job-processor` during the 7s window to observe `Outstanding ACKs: 1`.<br>5. Observe transaction completion at 7s and late `msg.Ack()` transmission. |
| Worker Temporarily Unavailable (Backlog Accumulation) | Worker pull loop is paused or stopped while upstream publishers continue publishing jobs to the stream. | JetStream persists all published messages safely in the `JOBS` stream buffer. Stream sequence increments with each new job, while consumer sequence remains paused at the last delivered position. No messages are dropped; backlog accumulates reliably on the broker. | 1. In Stage 3, toggle the worker state to `PAUSED` (or stop pull loop).<br>2. In Stage 1, submit 3 to 5 jobs.<br>3. Inspect `nats consumer info JOBS job-processor` to observe `Unprocessed Messages > 0` accumulating in backlog.<br>4. In Stage 3, toggle the worker back to `RESUME`. Observe all accumulated backlog messages pulled and processed in sequence without message loss. |
| Worker NAKs Message (Explicit NAK) | Worker receives a message, detects a processing failure, and explicitly sends `NAK` (`msg.Nak()`) instead of `ACK`. | NATS treats the message as not successfully processed and immediately marks it eligible for redelivery. Redelivery counter increments (`meta.NumDelivered` from 1 to 2). The worker receives the message again on attempt #2 and ACKs upon success. | 1. In Stage 3, expand Failure Lab and click `Arm NAK`.<br>2. In Stage 1, submit a job.<br>3. Observe terminal logging `[NAK TRIGGERED]` and `[NAK SENT]`.<br>4. Observe immediate redelivery `[REDELIVERED]` (attempt #2) followed by `[COMPLETED]` and `[ACK SENT]`.<br>5. In `nats consumer info JOBS job-processor`, observe `Redeliveries: 1`. |
| Worker Terminates Message (msg.Term()) | Worker receives a message, determines it is poisoned or permanently unprocessable, and sends a terminal acknowledgement (`msg.Term()`). | NATS marks the message as permanently terminated. The message is NOT redelivered to this consumer. The consumer ACK progress moves forward past the terminated message (`Ack Floor` advances). The message remains stored in the stream buffer. | 1. In Stage 3 Failure Lab, click `Arm TERM`.<br>2. In Stage 1, submit a job.<br>3. Observe terminal logging `[TERM TRIGGERED]` and `[TERM SENT]`.<br>4. Verify in terminal that the message is never redelivered.<br>5. In `nats consumer info JOBS job-processor`, observe `Outstanding ACKs: 0`, `Redeliveries: 0`, and `Ack Floor` has advanced. |
| Consumer State Retention Across Restart | Worker consumes some messages and consumer has acknowledged progress. Worker process or container is stopped and restarted without deleting the durable consumer. | NATS server retains the durable consumer state. Previously acknowledged messages are NOT redelivered. Any pending/unacknowledged stream messages remain queued and are delivered to the reconnected worker starting from the retained ACK floor. | 1. In Stage 1, submit 2 jobs and verify both complete with `[ACK SENT]`.<br>2. Toggle worker pull loop to `OFF` (or stop processor service).<br>3. In Stage 1, submit 2 more jobs.<br>4. In Stage 3, click `Restart Worker` (or restart service in terminal).<br>5. Observe terminal logging `[DURABLE STATE] Consumer connected | Ack Floor: Stream Seq 2`. Observe that jobs 1 and 2 are NOT reprocessed; only jobs 3 and 4 are delivered and processed. |
