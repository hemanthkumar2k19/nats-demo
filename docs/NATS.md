# NATS Terminology & Lifecycle Reference

| Word / Term | Description | Type & Location (Where It Lives) | Component (Core NATS / JetStream) | Lifecycle (Create / Change Config / Delete) |
| :--- | :--- | :--- | :--- | :--- |
| **NATS Server (`nats-server`)** | Core daemon process and clustering node that routes messages, handles subscriptions, and hosts JetStream storage engines. | **System Daemon / Binary**<br>Lives on Server Host / Container | Both (Core NATS & JetStream) | **Create**: Start executable (`nats-server -c nats.conf`) or deploy container/pod.<br>**Change Config**: Edit configuration file and reload without downtime via `nats-server -signal reload` (SIGHUP).<br>**Delete/Clean**: Stop process gracefully via `nats-server -signal stop`, terminate container, or kill process. |
| **Subject** | Dot-separated string addressing token (e.g. `jobs.submitted`) used to direct messages to subscribers or stream filters. | **Routing Token / Address**<br>Lives in Core NATS (Server Memory) | Core NATS | **Create**: Created dynamically in memory upon first publish or subscription; no prior registration required.<br>**Change Config**: Update subject string in publisher or consumer application code.<br>**Delete/Clean**: Automatically removed from broker memory as soon as no active clients or stream filters reference it. |
| **Queue Group** | Server-side dynamic 1-of-N load balancing mechanism distributing incoming messages across a group of subscribers. | **Dynamic Load Balancer**<br>Lives in Core NATS (Server Memory) | Core NATS | **Create**: Worker calls `nc.QueueSubscribe("subject", "group_name", handler)`.<br>**Change Config**: Update queue name or handler options in client code and reconnect.<br>**Delete/Clean**: Automatically dissolved by server when the last worker in the queue group unsubscribes or disconnects. |
| **Stream** | Persistent, append-only message log stored on disk or memory that captures and retains messages matching subject filters. | **Commit Log / Storage Engine**<br>Lives in JetStream (Server Disk / Memory) | JetStream | **Create**: CLI (`nats stream add <NAME>`), client SDK (`js.CreateStream(ctx, cfg)`), or configuration file.<br>**Change Config**: CLI (`nats stream edit <NAME>`) or client SDK (`js.UpdateStream(ctx, cfg)`). Update subjects, limits, or retention.<br>**Delete/Clean**: CLI (`nats stream rm <NAME>`), client SDK (`js.DeleteStream(ctx, "<NAME>")`), or purge messages via `nats stream purge <NAME>`. |
| **Durable Consumer** | Server-side cursor and state record on a Stream tracking read position, delivery attempts, and pending ACKs. Resides inside broker; survives restarts. | **Stateful Cursor / Read View**<br>Lives in JetStream (Server Disk / Memory) | JetStream | **Create**: CLI (`nats consumer add <STREAM> <NAME>`) or client SDK (`js.CreateOrUpdateConsumer(ctx, stream, cfg)` with `Durable` set).<br>**Change Config**: CLI (`nats consumer edit <STREAM> <NAME>`) or client SDK (`js.UpdateConsumer(ctx, stream, cfg)`). Update filters, ack wait, max deliver.<br>**Delete/Clean**: CLI (`nats consumer rm <STREAM> <NAME>`) or client SDK (`js.DeleteConsumer(ctx, stream, name)`). |
| **Ephemeral Consumer** | Temporary server-side cursor on a Stream for short-lived queries or ad-hoc tasks; automatically discarded when inactive. | **Transient Cursor / Read View**<br>Lives in JetStream (Server Memory / Disk) | JetStream | **Create**: Client SDK creates consumer without a `Durable` name (e.g., `js.OrderedConsumer()` or anonymous consumer).<br>**Change Config**: Immutable; discard and re-create with new parameters if configuration needs to change.<br>**Delete/Clean**: Automatically deleted by the server when client disconnects and `InactiveThreshold` (default 5s) expires. |
| **Pull Consumer Subscription** | Client-driven batch consumption model where worker applications pull messages on demand (`Fetch()` / `Consume()`). | **Client Pull Handle / Fetch Loop**<br>Lives on App Side (Worker Process) | JetStream | **Create**: Worker binds to consumer via client SDK: `consumer.Fetch(batch)` or `consumer.Consume(handler)`.<br>**Change Config**: Adjust batch size, fetch timeout, or max in-flight parameters in client worker code.<br>**Delete/Clean**: Call `consumeContext.Stop()`, close subscription context, or terminate worker process. |
| **Push Consumer Subscription** | Server-driven delivery model where the NATS broker proactively pushes messages out to a designated deliver subject. | **Client Listener / Deliver Subscriber**<br>Lives on App Side (Worker Process) | JetStream | **Create**: Defined in Consumer config with `DeliverSubject` set, then client subscribes to that deliver subject.<br>**Change Config**: Update `DeliverSubject` on consumer configuration via CLI or SDK.<br>**Delete/Clean**: Unsubscribe client listener and delete the underlying Consumer on the broker. |
| **Worker (Processor / Client)** | External application process or microservice (e.g., `processor-service`) running business logic that connects to NATS. | **Microservice / Executable Process**<br>Lives on App Side (Container / Pod / Host) | Both (Core NATS & JetStream) | **Create**: Build and deploy application binary, Docker container, or Kubernetes Pod.<br>**Change Config**: Update environment variables (e.g., `NATS_URL`), reconfigure application flags, and restart/roll out worker.<br>**Delete/Clean**: Stop process (`SIGTERM`), stop Docker container, or delete Kubernetes deployment. |
| **Acknowledgment (ACK / NAK / TERM)** | Per-message protocol control signals sent from a worker back to the server-side Consumer to update message delivery state. | **Protocol Control Frame / Signal**<br>Lives In-Flight (App Side -> JetStream) | JetStream | **Create**: Worker calls `msg.Ack()`, `msg.Nak()`, `msg.Term()`, or `msg.InProgress()` on received message.<br>**Change Config**: Configured on Consumer via `AckPolicy` (Explicit, All, None) and `AckWait` timeout duration.<br>**Delete/Clean**: Protocol exchange completes as soon as broker records acknowledgment or schedules redelivery. |
| **Key-Value Bucket (KV)** | Distributed Key-Value store abstraction implemented internally on top of a JetStream stream (`KV_<bucket>`). | **KV Store Abstraction (Stream)**<br>Lives in JetStream (Server Disk / Memory) | JetStream | **Create**: CLI (`nats kv add <BUCKET>`) or client SDK (`js.CreateKeyValue(ctx, cfg)`).<br>**Change Config**: CLI (`nats kv update <BUCKET>`) or client SDK (`js.UpdateKeyValue(ctx, cfg)`). Modifies TTL, storage, or history depth.<br>**Delete/Clean**: CLI (`nats kv rm <BUCKET>`), client SDK (`js.DeleteKeyValue(ctx, "<BUCKET>")`), or purge keys via `nats kv purge <BUCKET>`. |
| **Object Store Bucket** | Chunked blob / large file storage abstraction implemented internally on top of a JetStream stream (`OBJ_<bucket>`). | **Blob Storage Abstraction (Stream)**<br>Lives in JetStream (Server Disk / Memory) | JetStream | **Create**: CLI (`nats object add <BUCKET>`) or client SDK (`js.CreateObjectStore(ctx, cfg)`).<br>**Change Config**: CLI (`nats object update <BUCKET>`) or client SDK (`js.UpdateObjectStore(ctx, cfg)`). Modifies description, storage, or TTL.<br>**Delete/Clean**: CLI (`nats object rm <BUCKET>`) or client SDK (`js.DeleteObjectStore(ctx, "<BUCKET>")`). |
